## What Drew does

- the first wire;

The test bench lives in `packages/tools/src/gate/`. It uses the real canvas and the real simulation, because the app's tray (4.2) and Run loop (4.4) come after this gate.

**Check on Safari in particular.** The list view opens on focus. Safari does not focus a button on a tap, so the panel may close before the tap lands. A fix, tested in WebKit, is in progress on `fix/list-view-safari`. If the list view closes on a plain tap on the iPad, note it.

## Automated evidence

- **Parity (rule 8).** All 19 content fixtures build byte-identically on six paths: commands, touch drag, touch tap-then-tap, pointer drag, pointer click-click and list view. CI runs this strict, so a partial or mismatched fixture fails CI.
- **Failure modes.** Each of the 8 broken fixtures shows its own tell in a recorded Run. Each is compared against the same robot with its fault fixed (run-animation e2e).
- **Golden runs.** 26 Runs match, now including wire flows (D78). The 100-run determinism sweep is green (G1).
- **The gate bench's own test.** `pnpm gate:g3:test` places all 8 Rolling Start parts by mouse, sees the wrong-type drop refused, wires the robot to match the fixture's 12 connections, runs with motion and no fault, and Stop restores the build byte for byte.
- **CI on main.** Green after the 3.x merges. Two problems are fixed:
  - **Placement tests.** The CI-only failures came from a test tray that let a mouse drag select page text. Fixed by e5920a1.
  - **Pan and zoom cost.** 3.7's limits were recomputed on every step. Now cached, so pan and zoom p95 dropped from 16.1 to 11.8 ms on CI.
