### Notes for later tasks

- **Tasks 3.2–3.4: the input seam.**
  - A claim on a pointer is final; nothing hands it back to the view. So a handler that wants taps on empty canvas (deselect, the second tap of tap-then-tap) has to pan by itself, or the router needs a release.
  - Claims get raw PointerEvents and must convert them to canvas coordinates themselves, because `screenOf` is private.
  - The router listens on the canvas only. So `beginPlacement` with a pointer from the tray needs listeners on the document.
- **Task 3.3.**
  - Crowded sockets: finding 2 and Question 1.
  - `hitTest` returns the topmost socket, so a covered socket cannot be hit.
  - Polarity marks: Question 4.
- **Task 3.7.** Basic zoom limits exist (`limitsFor` in camera.ts): from half the fitting zoom up to 4, with the view's centre held over the content.
- **The app.**
  - The renderer stops Pixi's shared `Ticker.system` and advances it from its own frames (surface.ts:398-399 and 574). Anything else in the app that uses Pixi needs its own ticker.
  - Names are rasterised when they are drawn. If the app loads a web font after mounting, it should call `setPrefs` again so the names redraw.
- **Task 3.8.** The iPad profile runs in Chromium, so iPad Safari (WebKit) is not exercised yet. The profile belongs in the harness.
