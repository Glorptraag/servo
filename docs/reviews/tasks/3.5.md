## Findings

1. **Medium. The distinctness test is close to vacuous.** Rule 14 / done-when. `packages/tools/test/e2e/run-animation.e2e.ts:325-339`.
   - "No two screenshots match" compares screenshots of different builds, each with its own camera framing. They would differ by more than 2% even if Run mode drew nothing.
   - The done-when is still met, because each fixture's probes (`:202-322`) find its tell in the pixels.
   - This test should not be read as the proof of distinctness. A meaningful version would compare each broken Run with the same build's Build-mode or tick-0 screenshot, and require a tell-sized difference.
   - The four robots that share a body (missing return, underpowered, short, reversed) make the comparison worth having.
2. **Medium. The short circuit's tell is small, and its colour is not checked.** Rule 9 / brief Section 11. Code: `overlay.ts:253-263` and `docs/run-animation.md` open question 8. Test: `run-animation.e2e.ts:266-272`.
   - The short is a wire between two neighbouring sockets, so its racing dots are hidden under them.
   - In the screenshot, the short looks like a dead robot with a thin red bar about 5% drained under the pack.
   - The e2e checks that the bar's fill and its empty end differ by more than 80. That would also pass for a dark, non-draining bar. It does not check that the fill is the power colour, which is the actual `drain` signal.
   - The tell is distinct from the underpowered pack: those dots are visible and that gauge is dark. But a child of six to eight may not read it. See question 2.
3. **Low. A tautological assertion in the stall test.** `packages/canvas/test/browser/run-animation.test.ts:127`.
   - `expect(nodePosition('motor-right')).toEqual(nodePosition('motor-right'))` compares a value with itself.
   - The claim in the test's name, "and nothing else does [shudder]", is therefore untested. It should compare `motor-right` at the even tick with `motor-right` at the odd tick.
4. **Low. The run loop's contract is only in the package docs.** Rule 6 / rule 14. `packages/canvas/src/interface.ts:146`; `animator.ts:132-137`.
   - A frame at the same tick as the last restarts the drawing. That clears the spin-up's dot travel, the tread phase and the scrape marks.
   - Task 4.4 might hold the spin-up by re-applying tick 0 every animation frame, which is the obvious way to do it. Then the dots would never flow.
   - If 4.4 re-sends the latest frame on pause, the scrapes would vanish.
   - The rule is in `docs/run-animation.md` ("A frame at the same or an earlier tick … starts the drawing again"; "applying tick 0's frame … and holding it"), but not in the `applyRunFrame` doc comment, which is what 4.4 builds against.
   - Either add one sentence there (a doc-only interface change, noted), or put it in 4.4's prompt.
5. **Low. The Run-animation e2e does not run in CI.** Rule 11 / plan P3-8. `packages/tools/test/e2e/run-animation.config.ts`; `.github/workflows/ci.yml:28-33`.
   - `e2e:run-animation` is a separate script, and `ci.yml` runs only lint, typecheck, `pnpm -r test`, validate-content and golden.
   - The committed reference screenshots therefore guard nothing until someone runs the script by hand.
   - The config says it is meant to merge with 3.8's harness once both land. That should be tracked so it is not lost.
6. **Low. The stall shudder ignores `prefers-reduced-motion`.** Brief Section 11. `animator.ts:362`; `state.ts:186`.
   - With reduced motion, the tweens and the spin-up flow are switched off, but a stalled part still jumps 2.5 px each way on every tick (15 Hz at 30 ticks a second).
   - That may be right, since the shudder is the teaching signal. It should be a deliberate choice. See question 3.

Not findings, noted for the record:
- The `subjects` line lists wires in string order (`w10` before `w6`). That is cosmetic.
- `CanvasSurface.flip` is public but not on the handle. It is test and list plumbing.
