## Findings

**F1 · high (blocking) · rule 9 (the ladder leads to the working build), safety of the circuit shown · `packages/content/challenges/level-2/what-if-one-cell.json:76–95` (ladder 0, trigger `no-loop` on the 1-cell pack) and `:19–` (ladder 2's swap).**

This is the builder's question (d). I reproduced it on the branch tip with the app's own `chooseLadder`, `narrowStep` and `doItCommand`.

1. Start with the 2-cell pack wired. The child places the 1-cell pack loose, which is the natural first move.
2. The Run shows `p1 no-loop`, so ladder 0 is chosen.
3. Its do-it wires the 1-cell pack's plus to side A of the switch and its minus to both DC motors' minus, while the 2-cell pack is still wired to the same points. The two packs end up in parallel.
4. The next Run shows `battery short-circuit`, `p1 short-circuit`, and both DC motors `low-voltage`. `judgeRun` returns `met: true`, because the goal only needs a forward speed between 60 and 220.

So the hint does the opposite of what the challenge teaches. The lesson is a swap, but the ladder builds a shorted pair of packs and the goal then reports it as done. A child who is told the goal is met on a short-circuit has been led into a faulty circuit by the hint, which is the rule-9 problem you described. I judge it blocking.

The test does not cover it. Its swap walk only tries prefixes of ladder 2's changes, which start with `remove-part`, so "place the new part first, remove the old one later" is never tried.

Suggested fix, content only:
- Make ladder 0 (and ladder 1) refuse to apply while the 2-cell pack is still wired. The simplest way is for the `no-loop` ladder's do-it to begin with `remove-part` of the 2-cell pack, as ladder 2 does, so the do-it is always the swap. `doItCommand` already skips changes the build has, and a `remove-part` of a part that is gone must not make it refuse. Check that case; if it refuses, order ladders so the swap comes first.
- Or add a ladder ahead of ladder 0, triggered by a `short-circuit` fault on a battery pack, whose do-it removes the 2-cell pack.
- Add a walk case that starts from "place the new part first". Also make the goal refuse a Run with a `short-circuit` fault, or add a test that no ladder's do-it ends in a short-circuit from any start.

I probed the sibling cases by hand and they are fine:
- `weak-battery-pack` with the 2-cell pack placed loose: ladder 0 swaps, and the goal is met with no short.
- `what-if-one-small-wheel` with the small wheel placed loose: ladder 0 moves the wheel, goal met.
- `what-if-one-cell` with the 2-cell pack removed first, loose or not: the ladders reach the swap.
