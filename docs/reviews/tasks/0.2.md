### New in this review (all minor; they can wait past the freeze)

- N10 · minor · note for task 1.2 · `src/circuit/wired.ts:414-430,563-579`, `docs/parts.md:52` · For `low`, `high` and `reversed`, `explainByControls` gives sim-core only the controls step of the rule. sim-core must apply the short step and the feeder step itself.
  - The schema's "with the short taken away" test is implemented only for a source joined to itself.
  - Example: a motor on a 2-cell pack wired beside a 1-cell pack. Both packs show `short-circuit`, and the motor at about 2.1 V reads `low`. Yet taking away the wires between the packs would meet its need.
  - Fix: write down the short step for the voltage-based ways, including loops made only of sources, before task 1.2 builds on it.
- N11 · minor · — · `src/circuit/wired.ts:593` · When a driver channel is at stop and the driver itself has no power, the motor is explained by `controls: [channel]`. But no setting of that channel powers it. The verdict is right, because the driver's `no-power` fault shows; the explanation should be `feeder`. This happened in 23 of 1,200 random circuits.
- N12 · minor · — · `src/circuit/wired.ts:295-318` · With two closed switches side by side across a pack, only the pack shows `short-circuit`. Neither switch shows `across-the-pack`, because each switch's ends are joined through the other, and a code comment (which the docs do not mention) says such a switch "carries nothing". Opening one makes the other show the fault. The short itself is still reported; only which switch gets blamed is incomplete.
- N13 · minor · note for later levels · `src/circuit/wired.ts:59-60,394-412` · Above 1,024 combinations, which takes 11 or more two-way controls, only single changes are tried. So an unmet need that two changes would fix becomes a fault: with 11 switches, a motor behind two open series switches shows `no-circuit`. This is documented, and no Level 1–2 kit comes close (at most 36 combinations).
- N14 · minor · note for task 1.5 · `src/circuit/wired.ts:662-671` · The control search reruns every time a control changes, including a bumper switch touching a wall. A pathological build of 10 open switches and 40 one-wire motors takes 818 ms, which would stall a 30-ticks-per-second Run for a moment. Kit-sized builds take a few milliseconds. Run the search outside the tick, or cache it per control state.
