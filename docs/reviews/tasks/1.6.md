## Questions for Drew

1. **Level 3's block rules.** Task 1.6 adds a small internal block-rule runtime to prove that Level 3 rules can plug in as data. A rule says "always", or "when an input reads above or below a level"; then it sets an output to a level. Each output keeps its last level, as a real microcontroller pin does.
   - Should it stay as an unexported, provisional seed that the Level 3 design (sub-draft 6) is free to replace, or be removed until then?
   - Recommendation: keep it, labelled provisional. Nothing in v1 reaches it, and the tick loop does not depend on it.
   - Either way, sub-draft 6 must settle two points:
     - When a rule stops holding, does its output keep its level, so the servo motor stays where it was sent? Or does it let go, so the servo holds and hums (the no-signal failure)?
     - Confirm that a microcontroller that loses power starts its program again from the beginning, as its record's failure mode already says.
2. **How far a brain's rules reach.** Brief Section 4 says that from Level 3, settings "can also be driven by rules in the brain". Through the program slot (task 0.4's interface), a rule reaches a part only along a signal line from one of the microcontroller's outputs, as in a real build. So a rule cannot set an LED's colour or a DC motor's speed setting directly.
   - Recommendation: signal lines only. That keeps the interface as it is, and keeps the real-robotics lesson that a brain commands parts through wires.
   - A part that a rule should drive gains a signal input in its record, which is data.
   - Setting settings directly would need a change to the interface's `BrainStep`.
