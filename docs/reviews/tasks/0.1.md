### New in this review

- N1 · minor · rule 6 · eslint.config.js:130-133 · The rule does not notice a relative path through the package's own pnpm symlink leaving the package, because `path.resolve` does not follow symlinks. `import { … } from '../node_modules/@servo/sim-core/src/solver.ts'` in canvas/src passes lint with `--max-warnings 0`, tsc and Vitest (verified in the scratch copy). This works for the internals of any declared dependency. Fix: reject relative specifiers that contain a `node_modules` segment, or compare real paths.
- N2 · minor · rules 2 and 6 · eslint.config.js:44 · Only `src/` is treated as shipped, yet src may relative-import same-package files outside it, and those files are exempt from both the package map and the purity rules. Two cases pass lint, tsc and Vitest (verified): canvas/src importing `../test/helpers.ts`, which re-exports `@servo/sim-core`; and sim-core/src importing `../lib/clock.ts`, which calls `Date.now()` and `Math.random()`. Fix: relative imports of code files from `src/` must stay inside `src/`.
- N3 · minor · rule 6 · eslint.config.js:74-96, eslint.config.js:131, eslint.config.js:136 · Three rarer forms slip past the package map (all verified):
  - A relative template is checked only up to its first expression, so `` import(`../${dir}/../../sim-core/src/solver.ts`) `` passes and loads under Vitest.
  - A package.json `imports` alias is not checked: adding `"#engine": "@servo/sim-core"` to canvas/package.json lets canvas/src import `#engine` with lint, tsc and Vitest green.
  - `import.meta.glob('../../sim-core/src/*.ts')` is not visited at all. tsc rejects it today only because no package has `vite/client` types yet.
- N4 · minor (info) · rule 2 · eslint.config.js:208 · Deliberate or obscure reads of the clock or randomness still pass lint: `Function('return this')().Date`, `Reflect.get(Math, 'ran' + 'dom')` and `new Intl.DateTimeFormat().format()`. Importing `node:perf_hooks` or `node:crypto` also passes lint, but tsc rejects it because sim-core has no Node types. These are better left to review.
- N5 · minor · — · CLAUDE.md:74-78, docs/stack.md:51-54 · Both say lint and tsc make imports "stay inside their package", go "only along the package map", and keep sim-core free of clocks. That holds for every ordinary import form, but N1–N3 are exceptions. Either close N1 and N2 or add one line saying deliberate forms are left to review.

None of N1–N5 can happen by accident in ordinary code. Each needs something that stands out in review: a `node_modules` segment in an import, shipped code placed outside `src/` against the documented convention, a contrived template, a package.json alias, or newly added ambient types. N1 and N2 are one-condition fixes, worth taking before merge if the builder is still on the branch.
