## Findings

File names without a folder are in `packages/tools/src/validate-content/`.

1. minor · rule 7 · terminology.ts:189, 225-233 · The character-name check works only on capital letters. `sparky the DC motor` passes, while `LiPo battery pack` is refused as `terminology.proper_name` because of a real mixed-case mark. README.md:160 and README.md:196 present the capitals check as the catch without saying that a lower-case nickname gets through. Every Level 1–2 fixture name passes. See question 3.
2. minor · rule 7 · terminology.ts:200 · A part name with no letters or digits skips the real-name check, so a robot-face emoji (U+1F916) or `???` passes even with a full components list. README.md:158 says every name must contain a listed real name, and a robot face is exactly what rule 7 bans. Fix: refuse a name with no words as `terminology.not_real_name`.
3. minor · rule 13 · README.md:101-114 · The format never says what is not a gloss, and task 2.5 needs that. CLAUDE.md:56 says "power line (red)" and "mechanical linkage / mount (grey)", which read literally make colour words glosses. Listed that way, they refuse 18 lines in 12 of the 14 schema example parts, such as the DC motor's "Needs: power (red), from plus round to minus.", and brief line 261's own example. Listing `servo` or `battery` as glosses refuses brief line 269's hint "The servo is waiting for a signal" (6 issues in 5 parts). One sentence would fix it: only a word that replaces a name, such as frame or brain, is a gloss. See question 2.
4. minor · rule 13 · validate.ts:117, README.md:94 · The orchestrator's note said the schema fixtures are the catalogue "in tests". The CLI also uses them as its runtime default while `packages/content` has no part file. This is documented and noted on every run. It is harmless for content, because tasks 2.3 and 2.6 wait on parts. But it is a reading that README.md:191-198 ("Decisions and open questions") does not list.
5. minor · — · cli.ts:93 · Two misuse messages hide the cause. A folder named directly that cannot be listed gives "No .json records in …" (exit 2), not EACCES. The first example at README.md:6, `pnpm validate-content packages/content`, also exits 2 today because content holds no records yet. So a definition-of-done run over all of content fails until task 2.4's arenas merge.
6. minor · — · README.md:33, validate.ts:105 · README.md:33 says terminology-file issues come first, but missing paths and unlistable folders are reported before them (validate.ts:85-98; the `ContentReport` doc gives the order correctly). Separately, a `components.json` that cannot be read gets the note "names no components" beside its `terminology.bad_file` line.
7. minor · process · CLAUDE.md:72 · This line still says `pnpm validate-content` "does not exist yet", on this branch and on the 0.4, 0.6 and 2.4 branches. The file is outside the builder's list, so the orchestrator should update it at merge.

## Questions for Drew

1. **D22 in practice.** Whole-word `points` also refuses the verb: "Turns its shaft so the wheel points forward." was refused. "…the battery pack that lives under the chassis" was refused too, because `lives` is on the test list. Which do you want?
   - Keep the bare words, and reword content or allow-list phrases. This is the default.
   - Ban scoring phrases instead, such as "score points", "earn points" and "extra lives".
2. **Glosses, colour marks and short names (finding 3).** Two cases:
   - the colour words `red`, `yellow` and `grey`, as in "power (red)";
   - the short names `servo`, `motor` and `battery`, which brief Section 12's own hints use.

   Are these fine on their own? Recommendation: yes. Task 2.5 lists as glosses only words that replace a name, such as frame and brain.
3. **Character names (finding 1).** Should `components.json` carry allowed qualifiers (sizes, cell counts, colours), so that a lower-case nickname beside a real name is refused? Default: no. The capitals check and the banned list carry it.
4. **Sequencing.** Tasks 2.1 and 2.5 are each blocked only by 0.5. Until 2.5 lands, a default run checks only the schema, and two notes say so.
   - Recommendation: dispatch 2.5 before or alongside 2.1.
   - Have the G2 checklist re-run `pnpm validate-content packages/content` with the real lists.
   - Tell 2.5 that the format refuses a `!` entry, because the schema already refuses exclamation marks, even though 2.5's spec lists them.
5. **Readings to queue under rule 13.** These are the builder's readings from README.md:191-198:
   - content blueprint names get the lists;
   - a part name must contain a listed real name, with no capitalised word outside it;
   - a gloss sits beside its name (the orchestrator's ruling; 15 fixture lines were reworded);
   - run records are checked against the schema only.
