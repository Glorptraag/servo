## Judgements

**(a) Capitalised-word rule: sound in principle, a trap in practice (F1).** A character name cannot be told from an ordinary sentence opener without a word list, so a list is the right mechanism, and the message names the fix (add to `words.json`). But the opener list is a closed set of about 170 lowercase words. I ran `capitalFindings` through the real lists:
- Refused: `Brisbane schools use this kit.`, `Undo the last wire.`, `Wheels spin.`, `Check the power line.`, `Watch the LED.`, `Press Run.`, `Look at the ultrasonic sensor.`, `Touch the bumper switch.`, `Slow down.`, `Connect the red wire.`, `Notice the caster.`, `Pick a kit.`, `Read the spec card.`, `Show me a hint.`, `Keep going.`, `Sensors read the line.`, `Now wire the motor.`, `Buzzy says the wires are swapped`.
- Passed: part names at the start (`Battery packs`, `Motor drivers`, `Servo motors`, `Ultrasonic sensors`, `Line sensors`, `Switch the power on.`), `Run`, `Stop`, `Try again.`, `Mount the chassis.`, `Both wheels turn.`

Plurals of listed words, common imperatives and every proper noun fail until someone edits `words.json`. Level 3+ content will hit this often. Not blocking because it fails loudly with a pointer to the fix and the current content passes.

**(b) Schema example: no CI step is affected.** CI runs the validator only on `packages/content` (`.github/workflows/ci.yml:32`); `pnpm golden` reads content issues only. The one issue is `packages/schema/fixtures/parts/chassis.json:31` ("move that point"), asserted in `validate-content-lists.test.ts:315-330` and passing. The sentence stays a loose end until a schema task rewords it (F3).

**(c) Collector reach.** Planted one banned word per form in `App.tsx`, ran `ui-copy.test.ts`, reverted with `git checkout` (status clean). Caught: JSX text, JSX `{'x'}`, template literal with and without substitution, `aria-label`, `title` (string and template), `alt`-adjacent `<title>` in SVG, `aria-valuetext`, `placeholder`, text-key object value, array element, ternary result, string concatenation (by word), banned word split across elements (by word). Missed: `&#33;` and `&nbsp;` HTML entities in JSX text (the raw entity is read, F4); capitalised character names such as `Buzzy` in UI copy (only the banned list and `!` are checked there, by design); CSS `content:` strings. A banned word added to `banned.json` reaches UI strings; a character name does not.

**(d) D22 holds.** `Collect points`, `two points apart` refused; `mount point`, `mount points`, `Mount Points`, `pointer`, `pointed` pass. Singular `point` is now banned as an ordinary word, so `the point of the wheel` is refused (F2).

**(e) No existing content text or golden changed.** Confirmed by the diff and `pnpm golden`.
