## Review points

1. Additive and typed (rule 6): PASS. `WireEvent`, `WirePath`, `WireInProgress` and the `wire` key in `CanvasEventMap` (interface.ts) are new; nothing existing changed. The app uses `canvas.on('wire', ...)` only. README notes the change.
2. Rule 4: PASS. The event is read-only information. Run mode: `ListViewDom.render` ends the wire when mode is not build, and the canvas test sets Run (wire-event.test.ts:144).
3. Steps aside and returns: PASS on landing on all three paths. `back()` asserts `aside` false, then reselects a part for the canvas paths before asserting the card shows. Cancelled wire: the app test does not cover it; the canvas test covers let-go and closed/hidden events only as `wire: null`, so the app's return after a cancel rests on the same `null` handler. Minor gap, see F1.
4. Default 2 (selection cleared by a socket press): the same as before 7.8, not a regression. 3.4 cleared the selection on any socket press, so a drag wire already left the card hidden until a part was selected. Tap-then-tap now matches drag. It is still a usability cost, see Q1.
5. List-view definition: the wire begins only when the opened port has `connect` actions and Build mode. Most ports in a part with free partners will qualify, so opening a port's Actions in the list view will hide the card. The list view is a screen-reader path and the panel is separate from the canvas, so on a 10-inch tablet the cost is small, but see F2 and Q2.
6. Parity: PASS (above).
7. Rule 7: no exclamation marks, praise or banned words in the new comments or README text.
