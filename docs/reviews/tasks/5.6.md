### Finding 2 (oversized links): closed

The caps live in one place, `packages/app/src/sharing/limits.ts`:
- a fragment of 32 KB;
- an inflated document of 256 KB;
- 100 parts;
- 200 wires.

How they are applied:
- `readShareFragment` measures the fragment before decoding it.
- Inflating goes through `pipeWithin`, which feeds 256 bytes at a time and stops at the cap. At most one piece's output, about 264 KB, can overshoot.
- Parts and wires are counted right after `JSON.parse`, before the author check, migration and validation, and counted again after migration.
- `shareLinkOf` refuses to make a link past any cap.

## Findings

1. **Blocking: merge conflict with main (task 5.3).** Process (rule 11) and rule 8. `packages/parent/src/accounts/view.tsx:1-5` and `:248-276` (branch lines).
   - The header comment conflicts, which is trivial.
   - The build list conflicts, which is not. On main, the list is rendered by `PartsListExport` (`parent/src/export/view.tsx:101-104`, one `<li>` per build, with `describe`). This branch renders its own `<ul>` with Copy link, the include-name checkbox and the hand-copy field.
   - A resolution must give each build both the parts-list action and Copy link. That means either a per-row action slot in `PartsListExport` or a deliberate layout of the two, with touch, pointer, keyboard and list paths for both and one status line.
   - After resolving, run `parent/test/browser/share.test.tsx`, which queries Copy link per row, and 5.3's export browser tests together.
   - `packages/app/README.md:112` ("Task 5.3 … merges after") is now stale.

2. **Medium: no ceiling on a valid build's size, so a crafted link can freeze the recipient's tab.** Rules 2 and 9 in spirit: failure should be a plain line, not a hung page. `packages/app/src/sharing/link.ts:25` (`MAX_DOCUMENT_BYTES = 1 MB`) and `link.ts:229-232` (no part or wire count check). The replay also starts by itself (`view.tsx:116`).
   - A link of about 40 KB holding 8,000 parts validates in about 640 ms.
   - On this loaded machine, `createSimulation` then takes about 37 s and 30 ticks take about 10 s. With 500 parts, a step takes about 80 ms.
   - The replay runs on the main thread at up to 4 steps a frame, so the page, including Stop, stops responding.
   - A Level 1–2 build is a few KB. Suggested fix: lower `MAX_DOCUMENT_BYTES` to something like 64 KB, and refuse a shared build with more parts or wires than the largest Level 1–2 kit allows (or a fixed cap such as 60 parts and 120 wires) as `refused`. Add a test with an oversized but valid build.

3. **Low: the parent view's copy overstates the guarantee once the name is ticked.** D21 and rule 7 (copy accuracy). `packages/parent/src/accounts/view.tsx:37`.
   - `shareIntro` says a link "never holds a child's name".
   - With "Include the build's name" ticked, the link holds child-written text, and D21's own concern is that this text can contain a child's first name.
   - Suggested wording: "…It never holds a child's profile. The build's name is included only if you tick the box below."

4. **Low: a test gap on the real page.** Test coverage. `packages/app/test/browser/sharing.test.tsx:221`.
   - The `index.html#share=` iframe test checks that the shared page opens and moves. It does not spy on `indexedDB.open` or `localStorage.setItem` in the frame, so the no-store claim for the real entry rests on code reading (`main.tsx:13`).
   - Asserting `frame.contentWindow.indexedDB.databases()` is empty, and that no `servo` keys are in its `localStorage` afterwards, would close it.

5. **Info.**
   - `highWater` and the part and wire ids (`p<n>`, `w<n>`) travel in the link. They reveal how many parts the child ever placed, which is not profile data.
   - The replay has no inputs (the canvas is read-only, so a manual switch cannot be flipped). A build that needs a switch press will sit still. The builder raised this as README question 5.
   - In a tester build, the invite gate still writes its own remembered-code key to `localStorage` before the shared page opens. This is not a child's store.

3. **Size cap for links (finding 2).** Should the cap be the largest Level 1–2 kit, or a fixed number?

4. **The replay runs until Stop.** Should it stop by itself after a set time, or when the robot leaves the arena?
