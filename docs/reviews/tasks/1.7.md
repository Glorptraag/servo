## Findings

1. minor · rule 2, done-when · packages/tools/src/golden-runs/summary.ts:51-76 and README.md "Not covered" · `frame.flows` is not in the golden files. Power-line currents come from the electrical solver (`sim-core/src/electrical/flows.ts`, the `wires` map) and are not a function of any recorded readout. Negating every line's current (M5) leaves all 26 Runs "same", yet task 3.5's dots and task 3.4's flow labels would run backwards. Adding a `wire:<id>` subject per power line (milliamps), signal line (signal) and drive linkage (rpm) at the same precisions would close it for about the cost of the existing summary. Question 1.
2. minor · process · packages/tools/src/golden-runs/run.ts:82, diff.ts:59-67, cli.ts:174-188 · Each part record is hashed whole, including spec-card text, teaching notes and `popularMechanics`. So an edit that changes no Run fails `pnpm golden` on every case that uses the part. M8, one word in the DC motor's `popularMechanics`, gave 18 DIFFERS, each "ticks: all N are the same". Task 6.5's copy pass and any spec-card fix would need a blanket `--accept` and an orchestrator note, which trains people to accept without reading. Either hash only the fields the simulation reads (ports, behaviour, failure modes, body), or report a hash-only change as a quiet status that `--accept` refreshes without failing the check.
3. minor · rule 14 · package.json:17-18 · `pnpm check` (the local definition of done, which CLAUDE.md's How to run calls "the same steps CI runs on every push") does not run `pnpm golden`. Only CI does, and task branches are merged locally and not pushed (only `origin/main` exists). `golden-cli.test.ts:237` checks one real case, switch-in-the-line. So a sim-core change that alters any other Run passes `pnpm check` and is first seen after merge. Add `&& pnpm golden` to `check` (17–35 s here), or have the orchestrator add it to CLAUDE.md's How to run and to rule 14's done list.
4. minor · readability · packages/tools/src/golden-runs/summary.ts:40-46 and :63 · A heading just under 360° rounds to `360`: `heading=360` in kit-circuit-crew.golden:36 and :930, and busy-workbench.golden:59. A sign flip of a tiny drift would then diff as `chassis.heading 0 → 360`, which reads as a full turn. Normalise 360 to 0 after rounding.
5. minor · readability · packages/tools/src/golden-runs/cli.ts:150 · "expect DOES NOT HOLD: no fault" puts what the fixture expects after the colon. It reads as "the Run showed no fault", which is the opposite of the M1 case it reported. Write "expect DOES NOT HOLD (expects: no fault)" or similar.
6. minor · tests · packages/tools/test/golden-cli.test.ts:218 · The comment "Past three cases, the hint names none." sits above the assertion where three cases are named. The no-names case is the one at :223-226. Move the comment there.
